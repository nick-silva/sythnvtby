Memory analysis (vbpack)

Browse captured frames and run an in-browser WRAM analyzer to annotate the .vbpack for later game-state overrides in Project tool.

How to capture for a good analysis
  1. On the emulator page, use Capture Frame while playing.
  2. For each high-level game state you care about (title, menu, intro/blimp, in-game, pause, etc.), capture 2–3 frames at different moments in that state (same State (high-level) name, optional different sub-state/note).
  3. Two frames with the same state name let the tool find bytes that stay stable inside that state. Captures with different state names let it find bytes that differ between states (candidates for game-state overrides).
  4. States with only one captured frame are labeled low confidence: they cannot prove intra-state stability and are excluded from the numeric comparison until you add more captures.

After analysis, Apply to manifest embeds results into manifest.json in memory only (your original file on disk is unchanged). Then Save annotated .vbpack downloads the updated pack — load that file in the paint tool. Download this pack (toolbar above) is still the unmodified file you opened. This flow does not create groups.json by itself — new packs often have only manifest.json until you save from the Project tool. The Project tool will auto-seed gameStatePools from this analysis when there is no groups.json in the zip, then write groups.json on Save .vbpack.
